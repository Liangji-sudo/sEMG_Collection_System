# IMU 数量推断修复方案

## 1. 问题描述

### 1.1 发现过程

在多轮采集任务 T010（2 个 Session，产生 2 个 H5 文件）中，可视化数据时发现：

- **Session 1 的 H5**：IMU 加速度计/陀螺仪波形显示**正常**
- **Session 2 的 H5**：IMU 波形显示**横线 + 三角峰**异常图案

即使删除同步结果后重新同步，Session 2 的问题依然复现。

### 1.2 症状分析

通过诊断脚本对比两个 H5 文件，发现关键差异：

| 指标 | Session 1（正常） | Session 2（异常） |
|------|:---:|:---:|
| BLE 硬件检测 IMU 数 (`imu1_num_imus`) | **1** | **1** |
| `imu1_all_ble` 的 `imu_index` 范围 | `[0]`（仅 1 个传感器） | `[0]`（仅 1 个传感器） |
| 同步后 `imu1a_100hz` 非零率 | **98.5%** | **5.2%** |
| 同步后 `imu1b_100hz` | **不存在** | **存在**（非零率 3.7%） |
| `imu1a_100hz` 加速度范围 | [-0.83, 1.43] g（正常） | [-6.41, 4.99] g（异常） |

**结论**：硬件实际只有 **1 个 IMU 传感器**工作，但 Session 2 同步时被错误检测为 **2 个传感器**，导致：

- IMU bin 被以错误的帧大小（40 字节 vs 正确 22 字节）解析
- 帧边界全面错位，95% 数据为零（横线），5% 为随机字节解析的垃圾值（三角峰）
- 多写了一个 `imu1b_100hz` 数据集，填充了垃圾数据

### 1.3 根因定位

**直接原因**：`_detect_num_imus_from_bin()` 函数的「整除检测」策略被截断的 bin 文件误导。

Session 2 的 IMU bin 文件未正确封尾（`data_size` 不是 22 字节整数倍），但**恰好**能被 40 字节整除（`40 = 4 + 2×18`，即 n=2 的帧大小），导致整除检测误判为 n=2。

**深层原因**：原 `_resolve_num_imus()` 无条件信任 bin 检测结果（"以 bin 为准"），即使 bin 检测值与 BLE 硬件握手报告值（`imu1_num_imus=1`）冲突。

**根本原因**：缺乏**多源交叉验证**和**数据质量校验**机制。

## 2. 扩展需求

用户反馈：实际硬件每个手环有 **3 个 IMU 传感器**，但因硬件损坏，实际上线运行时可能只有 1、2、3 个传感器正常工作。系统需要**自适应检测**哪些传感器在正常工作。

## 4. 解决方案

### 4.1 架构：多源融合 + 双层校验

```
┌─────────────────────────────────────────────────────────────┐
│                    IMU 数量决策流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Layer 1: 数量推断 (_resolve_num_imus)                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                  │
│  │ BLE 实测  │  │ BLE 握手  │  │ Bin 检测  │                  │
│  │(all_ble)  │  │ (attrs)  │  │ (整除/帧ID)│                  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘                  │
│       │              │              │                        │
│       └──────────────┼──────────────┘                        │
│                      ▼                                       │
│          ┌──────────────────────┐                            │
│          │  冲突？→ 帧ID验证裁判  │  ← 对冲突候选值分别验证    │
│          │  一致？→ 直接采用      │                            │
│          └──────────┬───────────┘                            │
│                     ▼                                        │
│              num_imus (1~3)                                  │
│                                                             │
│  Layer 2: 质量校验 (_validate_imu_sensor_data)               │
│  ┌──────────────────────────────────────────────┐           │
│  │  每个传感器独立检测:                           │           │
│  │  • 非零率 < 10% → 疑似损坏                     │           │
│  │  • Acc 范围 > ±8g → 字节错位                   │           │
│  │  • 方差 ≈ 0 → 传感器卡死                       │           │
│  │  • 含 NaN/Inf → 数据损坏                      │           │
│  └──────────────────┬───────────────────────────┘           │
│                     ▼                                        │
│        active_count → 写入 H5 attrs                          │
│        损坏传感器 → 数据集截断为 0 行                          │
│                                                             │
│  Layer 3: 可视化推断 (_infer_imu_counts)                     │
│  ┌──────────────────────────────────────────────┐           │
│  │  优先级:                                      │           │
│  │  1. imu{dev}_active_count (sync 校验结果)    │           │
│  │  2. all_ble imu_index (BLE 实测)             │           │
│  │  3. 已加载数据 + 质量过滤                      │           │
│  │  4. H5 attrs (BLE 握手)                      │           │
│  │  5. 默认 2                                   │           │
│  └──────────────────────────────────────────────┘           │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 各场景覆盖

| 场景 | BLE | Bin | 帧ID验证 | 质量校验 | 结果 |
|------|-----|-----|---------|---------|------|
| 3 个全好 | 3 | 3 | n=3 ✓ | 3 active | **3** ✓ |
| 3 个坏 1 个 | 3 | 3 | n=3 ✓ | 2 active | **2** ✓ |
| 1 个, bin 截断 | 1 | 2 | n=1 ✓, n=2 ✓ | 1 active | **1** ✓ |
| BLE 限传 2, bin 有 3 | 2 | 3 | n=2 ✓, n=3 ✓ | 保守取小 | **2** |
| BLE 限传 1, bin 有 2 | 1 | 2 | 双方均通过 | 取更小者 | **1** |

### 4.3 具体修改

#### 4.3.1 `bin_sync_tool.py` — 同步侧

**新增函数：**

- **`_verify_imu_count_fits_bin(imu_bin_path, num_imus)`**：快速验证给定的 `num_imus` 能否正确解析 bin 帧结构（通过 `_verify_imu_frame_ids` 检查帧 ID 递增序列）
- **`_validate_imu_sensor_data(all_data, num_imus)`**：抽样 500 帧校验每个传感器数据质量，检测指标包括：
  - 非零率 < 10%：正常 IMU 数据几乎不存在精确零值
  - Acc 范围 > ±8g：超出 ±2g 传感器 4 倍余量，确定字节错位
  - 方差 ≈ 0：传感器卡死，输出恒定值
  - NaN/Inf：数据损坏

**修改函数：**

- **`_resolve_num_imus()`**（重写）：
  - 收集三重数据源：BLE 实测（`all_ble`）、BLE 握手（H5 attrs）、Bin 检测
  - 冲突时启动帧 ID 验证裁判：对冲突候选值分别调用 `_verify_imu_count_fits_bin`
  - 选择帧 ID 递增序列得分最高的一方
  - 双方均未通过验证时，保守取较小值

- **`_sync_imu_100hz()`**（增强）：
  - `np.empty` → `np.zeros`：防止未初始化内存残留为垃圾数据
  - 添加缺失的 `else` 分支：`k >= len(imu_data)` 时正确填零
  - 写入后调用 `_validate_imu_sensor_data` 进行质量校验
  - 损坏传感器数据集自动截断为 0 行（防止可视化加载垃圾数据）
  - 写入 H5 attrs：`imu{dev}_active_count`、`imu{dev}_active_indices`

#### 4.3.2 `calibrate_tool.py` — 可视化侧

**修改函数：**

- **`_infer_imu_counts()`**（增强）：
  - 新增最高优先级：`imu{dev}_active_count` attr（sync 阶段写入的校验结果）
  - 可视化侧质量过滤：排除非零率 < 5%、Acc 范围 > 16g、方差 ≈ 0 的数据
  - 增强诊断日志：显示多源信息及冲突警告

#### 4.3.3 `tools/diagnose_imu.py` — 诊断工具（新增）

用于对比两个 H5 文件的 IMU 数据健康状态，输出：
- H5 attrs（`sync_status`、`imu_num_imus` 等）
- `imu_all_ble` 和 `imu*_100hz` 数据集的形状、数值范围、非零率
- IMU bin 文件的自动检测结果
- 两个 Session 的关键差异对比

用法：
```bash
python tools/diagnose_imu.py <session1.h5> <session2.h5>
```

## 5. 边界情况覆盖

### 5.1 Bin 文件截断

**场景**：采集异常中断导致 bin 文件未正确封尾，`data_size` 不是正确帧大小的整数倍。

**处理**：
1. 整除检测失败 → 策略 2（帧 ID 验证）接管
2. 若策略 2 也失败 → 策略 3（最佳余数）兜底
3. 若检测结果与 BLE 冲突 → 帧 ID 验证裁判二次确认

### 5.2 BLE 带宽限制漏传

**场景**：BLE 为节省带宽只传输部分传感器数据，但 SD 卡 bin 记录了全部传感器。

**处理**：
- Bin 检测 > BLE 时，若双方帧 ID 验证均通过 → 保守取 BLE 值（避免引入未经验证的额外传感器）
- 若 Bin 帧 ID 验证通过但 BLE 值验证失败 → 取 Bin 值（BLE 确实漏传）

### 5.3 传感器硬件损坏

**场景**：传感器物理损坏，输出全零、常量值或随机噪声。

**处理**：
1. 同步阶段：`_validate_imu_sensor_data` 检测并标记为 inactive
2. 可视化阶段：`_infer_imu_counts` 过滤低非零率/异常范围数据
3. 损坏传感器数据集被截断为 0 行，不影响正常传感器显示

### 5.4 旧同步残留数据

**场景**：之前用错误的 `num_imus` 同步过，残留了不存在的传感器数据集。

**处理**：
1. 同步时：超出当前 `num_imus` 范围的数据集被截断为 0 行
2. 同步时：质量校验标记为 inactive 的数据集被截断为 0 行
3. 可视化时：0 行数据集不会被加载，不影响显示
