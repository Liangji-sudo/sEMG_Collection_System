## 用户

continual-gesture-3-animation.js, discrete-gesture-animation.js分别是连续手势3的labjs实验动画,离散手势动画。

realtimeEngine.js的作用是作为后端的数据调度功能。主要负责连接ble_server.py(websocket)读取蓝牙数据(emg信号)一个发送给前端实时显示,一个发送给储存模块。

我目前这个数据采集软件,有4个采集任务:离散手势采集任务,连续手势1采集任务,连续手势2采集任务,连续手势3采集任务.

离散手势采集任务,是一个开环的采集过程,他的采集引导逻辑就是简单的利用对应的labjs动画来提示受试者做出相应的动作。

连续手势的采集任务全部都是闭环采集(就是受试者会有输入给采集系统,然后显示比如光标来反馈给受试者)

连续手势1,连续手势2的采集任务,受试者需要通过动捕数据来解算出食指关节从0-90°,或者拇指食指间的距离的过程来映射到采集引导区域的同心圆光标上,然后根据引导同心圆的运动来运动,从而完成采集。

连续手势3的采集任务,受试者也需要通过动捕数据来解算出手掌翻转的角度来控制光标做半圆运动,使其跟随一个半圆来回运动的引导区域完成掌心向下到向上再到向下的运动。

## 我的方案建议

### 1. 数据通信架构

我建议动捕数据流走和EMG相同的路径：

```
[Python后端]
ble_server.py (EMG数据)  ──┬──WebSocket──> realtimeEngine.js ──WebSocket──> 前端
                          │                     │
mocap_server.py (动捕数据) ─┘                    ├─> waveformController (EMG显示)
                                               ├─> animation-input-interface.js (动捕→动画输入)
                                               └─> storage (数据存储)
```

**为什么这样设计：**
- 统一的数据入口，便于管理和同步时间戳
- `realtimeEngine.js` 已经有数据调度的基础设施
- 可以方便地实现EMG和动捕数据的时间对齐
- 前端只需维护一个WebSocket连接
- mocap_server.py 可以独立开发和测试

**mocap_server.py 发送的数据格式建议：**
```python
{
    "type": "mocap",
    "timestamp": 1234567890.123,
    "channels": {
        "finger_joint_angle": 45.2,      # 连续手势1: 食指关节角度 0-90°
        "thumb_index_distance": 3.5,     # 连续手势2: 拇指食指距离 cm
        "palm_rotation_angle": 120.0     # 连续手势3: 手掌翻转角度 0-180°
    }
}
```

### 3. collection-controller.js 标定流程

在 `startContinualGestureCollection()` 中新增标定环节：

```
[用户点击开始]
    │
    ▼
[播放指导视频/动画] ─── "请观看示范动作"
    │
    ▼
[标定最小值] ─── "请做出最小动作（如：手指完全伸直），保持3秒"
    │                  └── interface.startCalibration() 开始记录
    ▼
[标定最大值] ─── "请做出最大动作（如：手指弯曲90°），保持3秒"
    │                  └── interface.endCalibration() 结束记录，计算min/max
    ▼
[准备阶段] ─── "标定完成，即将开始采集..."
    │
    ▼
[开始正式采集] ─── animation.js 从 interface.getNormalizedInput() 获取输入
```
