## 🐛 常见问题排查

### 问题 1：HLS 录制未启动

**症状**：配置摄像头后，没有看到 HLS 启动日志

**检查**：
```bash
# 检查 ffmpeg 进程
tasklist | grep ffmpeg

# 检查临时目录
ls storage/video/temp/left/
```

**解决**：
- 确认 ffmpeg 已安装
- 检查摄像头是否被其他程序占用
- 查看 camera_server 日志

### 问题 2：预览帧是黑色或报错

**症状**：点击预览后，图像是黑色或显示错误

**检查**：
```bash
# 检查临时分段文件
ls storage/video/temp/left/*.ts
```

**解决**：
- 确认 HLS 录制已启动
- 等待几秒让分段文件生成
- 点击"刷新"按钮重试

### 问题 3：MP4 无法播放

**症状**：生成的 MP4 文件无法打开

**检查 Node.js 日志**：
- 查找"合并分段"的日志
- 查找是否有 ffmpeg 错误

**解决**：
- 确认所有分段文件都存在
- 检查 ffmpeg 版本是否支持 concat demuxer
- 手动运行合并命令测试

### 问题 4：临时文件占用磁盘

**症状**：`storage/video/temp/` 目录很大

**原因**：HLS 持续录制会生成大量分段文件

**解决**：
- 正常情况下，每次保存 MP4 后会自动清理
- 手动清理：
  ```bash
  rm storage/video/temp/left/*.ts
  rm storage/video/temp/left/*.m3u8
  ```

## 📊 性能参考

### HLS 录制

- **CPU 占用**：5-15%（取决于分辨率和帧率）
- **磁盘占用**：~1GB/小时（1280x720@30fps）
- **分段文件**：每秒 1 个（~1-2MB/个）

### 合并速度

- **76 个分段**（76 秒视频）：~2-3 秒
- **300 个分段**（5 分钟视频）：~5-10 秒

测试完成后，验证这些关键优势：

   - 播放 MP4，第一帧应该是按空格键的画面
