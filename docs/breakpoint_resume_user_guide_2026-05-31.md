# 断点续采功能使用说明

本文档面向现场采集工作人员，说明在采集过程中遇到腕带异常时，如何使用“异常中断”和“断点续采”功能，尽量保留已经完成的采集数据。

## 1. 什么时候需要使用异常中断

采集过程中，如果出现以下情况，建议点击右侧采集界面的“异常中断”按钮：

- 某一只腕带突然没电、断连或明显不工作
- 某一只腕带信号突然异常，例如持续平线、严重噪声、信号质量明显变差
- 两只腕带数据不同步，例如左右 EMG 窗口红线位置明显不一致
- 采集过程中出现严重丢包，导致当前任务后续数据不可信
- 其他工作人员判断当前 H5 后续数据已经无效的情况

注意：“异常中断”和普通“停止”不同。

- “停止”：表示工作人员主动停止本次采集，不会生成可续采任务
- “异常中断”：表示当前任务因为设备或信号问题被打断，系统会保存断点，后续可以续采

## 2. 异常中断后的操作流程

在采集界面点击“异常中断”后，系统会立即冻结当前采集记录，并弹出异常原因选择窗口。

操作步骤：

1. 点击“异常中断”
2. 在弹窗中选择原因，例如“设备没电”“丢包严重”“双设备不同步”“信号异常”或“其他”
3. 系统会关闭当前 H5 文件，并把它标记为异常中断
4. 系统自动返回初始界面
5. 初始界面会显示“断点续采”按钮

点击“异常中断”的瞬间，系统会停止继续写入当前 H5。弹窗期间不会继续把后面的采集提示和腕带数据写进这个 H5。

## 3. 异常中断数据保存在哪里

异常中断后，断点信息首先保存在当前采集生成的 H5 文件中，而不是马上生成一个单独的断点文件。

H5 文件一般保存在项目目录下的 `storage/` 目录中，例如：

```text
storage/采集任务类型/采集分类/姿态/状态/受试者编号/xxx.h5
```

异常中断的 H5 内部会记录：

- `collection_status = abnormal_interrupted`
- 中断原因
- 中断时间
- 当前 session / stage / gesture 进度
- 当前采集配置
- 乱序手势队列或连续手势进度
- 当前 segment 信息
- 本段对应的腕带设备和 bin 文件信息

如果需要在重启软件后恢复断点，可以使用后台工具从这个 H5 中导出 `.breakpoint.json` 文件。

## 4. 不重启软件时如何续采

如果异常中断后没有关闭软件，工作人员已经重新连接好两只正常腕带，可以直接续采。

操作步骤：

1. 确认两只腕带已经重新连接并工作正常
2. 在初始界面点击“断点续采”
3. 系统进入上次中断的采集任务界面
4. 确认界面显示的轮次、Stage、手势进度正确
5. 点击“开始续采”
6. 系统从上次异常中断的位置继续采集

如果点击普通“采集”按钮，系统会认为工作人员要开始一个新的采集任务，而不是续采旧任务。

## 5. 重启软件后如何续采

如果异常中断后关闭了软件、重启了系统，首页通常不会直接显示“断点续采”按钮。此时需要先从历史 H5 导出断点文件，再导入恢复。

操作步骤：

1. 打开后台或 HDF5 工具
2. 进入“历史断点”页面
3. 扫描 `storage/` 数据目录
4. 找到状态为异常中断、且未被续采的 H5 文件
5. 导出 `.breakpoint.json` 文件
6. 回到采集系统初始界面
7. 点击“导入断点文件”
8. 选择刚才导出的 `.breakpoint.json`
9. 页面出现“断点续采”按钮
10. 点击“断点续采”
11. 确认设备正常后点击“开始续采”

导入的 `.breakpoint.json` 文件本身不会被复制到项目目录。系统只是读取文件内容，并把断点信息写入浏览器缓存，用于恢复采集。

## 6. 多轮采集时的续采规则

如果原任务是“全部轮次采集”，断点续采会包含已经完成的轮次进度。

例如：

```text
总共 3 轮
第 1 轮已完成
第 2 轮采到第 18 个手势时异常中断
```

续采时系统会恢复到：

```text
第 2 轮，第 18 个手势附近继续
```

当前轮次完成后，系统会继续进入后续轮次，例如第 3 轮。已经完成的第 1 轮不会重新采。

## 7. 续采后会生成什么数据文件

断点续采不会继续写同一个 H5 文件，而是新建一个新的 segment H5 文件。

这样做的原因是：

- 避免异常中断的 H5 被继续写坏
- 避免更换腕带后设备和 bin 文件混在同一个 H5 中
- 每一段采集都能独立记录对应的腕带设备、bin 文件和 frame 范围
- 后续同步和排查问题更安全

因此，一次异常中断加续采后，通常会有至少两个 H5：

```text
segment 1：异常中断前的数据，collection_status = abnormal_interrupted
segment 2：续采后的数据，is_resumed = true
```

后台工具会显示这些 segment 的关系，便于确认哪一个 H5 被哪一个续采文件接上。

## 8. 常见问题

### 8.1 点了异常中断后，断点文件在哪里？

刚点击异常中断时，没有单独的 `.breakpoint.json` 文件。断点信息先保存在异常中断的 H5 文件里。

如果需要 `.breakpoint.json`，需要到 HDF5 工具的“历史断点”页面，从异常中断 H5 中导出。

### 8.2 为什么普通返回首页后看不到断点续采按钮？

这是正常设计。

只有点击“异常中断”并自动返回首页后，系统才显示“断点续采”按钮。普通返回首页表示工作人员当前没有明确选择续采，所以不会显示续采入口，避免误操作。

### 8.3 导入断点文件后，文件被放到哪里？

导入的 `.breakpoint.json` 文件仍然留在原来的磁盘位置。系统不会复制这个文件。

导入时，系统只读取文件内容，并把断点信息写入浏览器缓存。

### 8.4 更换腕带后可以续采吗？

可以。续采会新建一个新的 segment H5，并记录当前连接的腕带设备和对应 bin 文件。旧腕带中残留的半段 bin 不会和新腕带的数据混在同一个 H5 segment 里。

### 8.5 什么时候不要点断点续采？

如果工作人员决定放弃上一次异常任务，想重新开始一个新任务，就不要点“断点续采”，直接点击普通“采集”即可。

## 9. 推荐现场操作规范

建议现场按以下规则执行：

1. 发现腕带、信号或同步异常时，立即点击“异常中断”
2. 不要用普通“停止”代替异常中断
3. 选择最接近的异常原因
4. 返回首页后，先处理硬件问题，例如充电、更换腕带、重新连接
5. 确认两只腕带都正常后，再点击“断点续采”
6. 如果软件已经重启，先用 HDF5 工具导出 `.breakpoint.json`，再在首页导入
7. 续采前确认界面显示的轮次、Stage、手势进度符合预期
8. 续采完成后，可在后台查看 segment 链路，确认异常段和续采段已关联
